# Research agenda: decide when relational information is worth using

Assessment date: 16 October 2026. This is a ranked research proposal, not an established novelty claim or a preregistration. The preferred direction below survives an initial literature screen only in a narrower form than “statistics improve graphs”; its decisive experiments have not been run.

## Recommendation

Investigate **whether the reliability and diversity of measured interactions can predict the benefit or harm of cross-channel forecasting on an unseen sensor system, before observing its forecast outcomes**. Start with an explicit decision between a competent channel-independent forecast and a competent relational forecast. Treat GATs as possible implementations/comparators, not the scientific contribution.

The practical setting is deploying forecasting to a newly configured sensor network with little history: more sensors offer useful predictors but also noisy estimates, shared drivers and unstable relationships. An operator needs to know whether extra channels improve the forecast enough to justify using them. The proposed output is a tested decision rule with interpretable failure conditions, not a picture of large attention weights.

**Why care?** A transferable decision rule could reduce harmful reliance on other sensors and avoid repeatedly tuning a bespoke graph for each deployment. **Why is the answer not obvious?** Strong dependence can be redundant with the target's own past; weak dependence can be predictive at a particular horizon; estimator agreement can reflect shared bias; and a useful relation may be unusable by a particular backbone. Those distinctions are partly established already. The nontrivial candidate is whether *finite-record reliability and complementary interaction information* help make the deployment decision beyond simple historical forecast validation, Pearson/lagged correlation, or existing adapters.

The substantial pyspi speedup changes what can be measured: use the broad current p90 catalogue, larger systems and meaningful record lengths to study these conditions. It does not itself make this a new contribution. An orders-of-magnitude runtime claim has not been independently benchmarked here; size production from current measured workloads.

## The discriminating experiment comes before the method

For target system s, horizon h and a *fixed pair of forecasters*, define the realised utility of using other channels as `Delta(s,h) = loss(independent) - loss(relational)`, with losses normalised using training-only scale. Positive means relational forecasting helped. The proposed predictor sees only permitted past observations, h, record length, missingness, model identity and interaction summaries. Source-domain historical outcomes may supervise it; held-out-system future outcomes may not.

Specify two separate deployment tracks: (A) past-only selection with no target-system forecast-validation budget, and (B) a fixed small target-system backtesting budget. Compare only methods with the same access within each track. Otherwise a purportedly “zero-shot” interaction selector can accidentally compete against a weaker baseline denied available historical labels.

**First gate: is there consequential headroom?** Reproduce both useful and harmful channel mixing across independent systems with competent, matched forecasters. Measure the difference between the best single global policy and an explicitly labelled, unattainable test-outcome oracle. If this gap is negligible, a selector has no useful job. Do not manufacture a gap using an intentionally weak latent model.

**Second gate: can descriptors predict that headroom out of system?** Use simple regularised prediction of Delta before any GNN: compare univariate summaries; Pearson/lagged summaries; all p90 distribution summaries; p90 plus reliability estimates from disjoint history blocks; and raw temporal embeddings. Use source-only nested validation and frozen test systems. Control context length, channel count, missingness and broad domain so that a successful selector cannot simply recognise “large/noisy dataset”. If p90 adds no transferable information over cheap summaries or equal-budget backtesting, drop the vocabulary-based method claim.

**Third gate: is graph structure necessary?** Only if the above works, compare the same node encoder with (1) independent pooling, (2) pooled edge descriptors, (3) fixed dense edge-conditioned message passing, (4) an edge-aware GATv2, and optionally (5) a graph transformer. Keep raw history, edge attributes, optimisation budget and missingness information matched. Separate statistical features entering attention logits, message values, or graph-level readout. A graph-level pooled representation might be sufficient; that would be a finding, not a failed architecture search.

**Fourth gate: do the conclusions transfer?** Freeze the selector and its operating threshold before evaluating held-out acquisition conditions, systems and a second forecaster family. A claim about one model should stay model-specific if it fails across backbones. Evaluate direction removal, matched catalogue subsets, duplicates/redundancy, and reliability-feature ablations. Do not reinterpret an attention or coefficient ranking as a physical cause.

## Application and scope

**Preferred development application: sensor-network forecasting, initially traffic**, because the decision to use neighbouring measurements and the availability/loss of sensors have a direct operational interpretation. [DCRNN's official repository](https://github.com/liyaguang/DCRNN) provides established traffic datasets and sensor-location/graph references. Use METR-LA and PEMS-BAY as candidate transfer checks, not as enough independent “systems” to train and validate a universal selector. Additional nonoverlapping networks or a separately justified domain are required for a general transfer claim. Their data availability, licence, missing-value conventions and TSFM pretraining contamination must be resolved before freezing a protocol. No datasets were downloaded in this review.

Traffic is not selected because it is presumed easier or novel. Its crowded literature makes the test stringent, and the known physical graph provides a comparator that EEG lacks. If adequate independent systems or uncontaminated evaluations are unavailable, narrow the claim or change the application before extensive training. Temperature/energy sensor networks are possible external replications, but their shared seasonal drivers must not be called physical coupling without evidence.

**EEG remains viable.** A well-designed cross-subject/session motor-imagery or state-decoding study could be valuable, with covariance/Riemannian, band-power and modern waveform baselines; [MOABB](https://moabb.neurotechx.com/) provides an established evaluation framework. The old TUH experiment is not a reason to abandon it. However, “these weights reveal seizure propagation” requires much stronger physiological and measurement evidence than classification. Prefer a domain collaborator and intervention/annotation-grounded endpoints before making that the central paper claim.

**Higher-risk alternative: semantic identifiability of learned interaction explanations.** Ask when equally predictive models admit conflicting statistical signatures, and what intervention-backed statement remains identifiable. This is intellectually relevant but “weights are not explanations” is already established, as the [assessment](assessment.md) explains. A paper would need a new precise identifiability result or an independently validated scientific use, not another coefficient-stability plot. Do not run this as a second parallel paper by default.

## Controlled systems and real shifts

Use at least two distinct generative families: linear delayed stochastic networks and nonlinear coupled systems, with common drivers and independent channels as controls. Hold out parameter regimes and graph realisations, not just random windows. Match target marginal distributions/forecast difficulty as far as possible and report residual distinguishability. Known coupling graphs validate what the generator does; they are not automatically optimal forecasting graphs.

Separate (i) observation changes with unchanged latent dynamics—record length, noise, sensor subset, sampling—(ii) changes in coupling that are visible in the available context, and (iii) unannounced future changes. No past-only selector can universally predict the third: two systems can share the entire observed history and have different future mechanisms. Do not promise safety or invariance under arbitrary shift. Sensor mixing, marginal transformations and downsampling can alter or destroy accessible information; they are not automatically label-preserving nuisances.

Use M = 16, 64 and 128 and T = 256, 1024 and 4096 as initial **scouting points**, not an approved full factorial grid. Increase sizes where they resolve a scientific contrast. Full p90 is now practical enough to be the principal bank candidate; compare it to a small representative set and measured cheap baselines. Large M is meaningful when it changes the estimation/generalisation regime, not because a bigger graph looks impressive.

## Evaluation and Gadi use

Split by independent subject/system/trajectory, keep related windows and transformed views together, and purge overlapping forecast contexts/targets at temporal boundaries. Preserve official real-data splits when appropriate. Fit every selector, scaler, imputer, feature filter, redundancy reduction and threshold using the permitted training/calibration data for that track. Save all split IDs, exclusions, raw predictions, checkpoints and resolved settings. Report uncertainty over independent systems or suitable temporal blocks; additional optimiser seeds do not enlarge the effective cohort.

Primary outcomes should be forecasting loss, rate and magnitude of harmful relational decisions, and decision regret against the fixed baseline policies. A selector that always abstains has zero relational harms but no benefit: report acceptance/coverage and lost utility too. Prespecify an application-relevant harm threshold and comparison margin using development data; do not retrofit them to the test results. “Risk-calibrated” must refer to a stated empirical calibration population unless a valid theorem and assumptions support a stronger claim.

Use compute to strengthen matched baselines, repeat independent systems, assess T/M scaling, and reserve confirmation environments. Follow [HPC.md](../../HPC.md): pinned source, one current computation identity per new bank, scout runtime/memory, then bounded PBS farms. Never infer a safe full-node concurrency from single-process peak RSS. Dense float32 edge features alone require `4*M*M*K` bytes per example before activations, masks and copies; at M=128, K=283 this is about 17.7 MiB. Faster pyspi does not remove quadratic downstream storage.

## What would make a workshop paper

A strong first submission would show one reproducible phenomenon: when finite-record relational evidence predicts transferable benefit, where it fails, and whether that decision needs graph structure. The contribution would be an informative, controlled answer plus a reproducible evaluation—not a collection of small improvements. A positive case needs a useful held-out decision benefit over equal-access cheap/backtesting baselines and existing adapters. A negative case needs enough oracle headroom, reliable measurements and sufficiently strong models to exclude the obvious underpowered/design explanations.

Do not call the direction frontier-pushing yet. The closest literature is close enough that replication and the second gate could eliminate it. If the only surviving distinction is “replace Pearson with 283 statistics and gain a few percent”, reject that framing. Before major Gadi expenditure, settle the exact difference from ChaTSFM and Choi et al., resolve independent-system data access, and run the headroom/descriptor tests. Those are the next research decisions; implementing a new attention block now would prematurely choose an answer.
